# Задача
Подготовить демо проект для настройки дашбордов и алертинга на основе логов в OpenSearch. 

# Требования
- в docker-compose.yml подготовить стенд для развертывания системы OpenSearch последней версии (с явным указанием версии).
- подготовить скрипт для отправки логов в OpenSearch
- OpenSearch должен вычитывать логи и отображать их
- настроить дашборд для мониторинга логов 
- настроить алерт для логов - отправлять сообщение на почту, если в логах появляются определенные записи.

# Детали
В логах, попадающих в OpenSearch должны быть следующие поля:
- process_id уникальный строковый идентификатор формата UUID, используется для корреляции нескольких логов. То есть логи с одним process-id относятся к одному процессу.
- event_timestamp - дата и время записи в лог
- service_name - название сервиса, отправившего лог
- event_message - сообщение лога

Для приема почты НЕ надо использовать реальные почтовые сервера. Достаточно поднять тестовый mailhog с UI, чтобы можно было зайти и посмотреть содержание алерта. 

Дашборд должен отслеживать появление в логах запси:
"This is a very important message"
Запись будет содержаться в поле event_message, но не обязательно полностью, возможно, в этом поле вместе с этой фразой будут и другие тоже. 

Отправка логов в OpenSearch:
Реализовать приложение на Spring Boot 4.1.1, в котором будет планировщик отправки логов. 
Логи отправляются каждые 1000 миллисекунд.
Отправка логов происходит пачками - в одной пачке 10 сообщений с одним process_id. 
Фраза "This is a very important message" должна присутствовать в одной из 10 пачек в одном сообщении из 10. 
Остальные фразы могут быть рандомными на английском языке. 

Срабатывание алерта:
Отправка сообщения на почту должна осуществляться максимально быстро после появления в логах искомой фразы.
